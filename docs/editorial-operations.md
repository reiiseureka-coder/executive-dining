# 店舗運営の操作と公開範囲

利用者は通常の入口から店舗を検索・比較し、運営者はメニューの「運営管理」から店舗の判断に進みます。利用権限はサーバーで確認します。固定の架空プロフィール・投稿による操作確認は管理画面の「テスト投稿を確認」にまとめています。利用者向けの店舗詳細には投稿テストを表示しません。

## 1店ごとの流れ

1. 候補追加：店舗名・名古屋市内の所在地・公式URLを登録します。まだ公開も事実確認もされません。追加は既存の運営者のみ、1日10店・全体200店までです。同じ送信IDの再送は重複登録されません。
2. 調査：公式ページの事実、確認日、出典、未確認事項を記録します。料理・単品価格・コース価格・税込区分・飲物・個室と半個室は元情報の意味を保ちます。
3. 本人判断：1店ずつ、会食候補として掲載するか理由を添えて選びます。高級店だけを条件にしません。住所等の基本情報が未確認なら承認できません。
4. 承認保存：承認済みの状態になります。画面には実際の公開設定と、承認した場合の結果を表示します。一般公開が停止中なら、承認しても一般公開されません。
5. 修正：確認記録を修正すると判断待ちに戻ります。事実の確認と会食候補としての採否は別々の操作です。

検索・料理・対応状況で絞り込み、20件ずつ表示します。店舗を切り替えても判断メモはその画面内で保持します。ページを閉じると未保存メモは失われます。確定は確認欄で明示します。通信結果が不明なら保存済みと表示せず、一覧再確認を案内します。

## 今回のDB提案（適用前）

`supabase/proposals/20261011010120_editorial_operations.sql` は次の3つのAPIを追加します。すべて既存の編集権限をサーバーで要求します。新しい運営者は登録しません。

- `dining_editor_context()`：一般公開・口コミ受付・候補追加の状態を読み取ります。
- `dining_create_candidate(text,text,text,uuid)`：範囲を絞った候補登録です。
- `dining_save_listing_decision(uuid,integer,text,text,boolean)`：表示された公開設定と店舗バージョンが一致するときだけ判断を保存します。旧 `dining_moderate_restaurant` のクライアント実行権限を外し、この入口に置き換えます。

公開設定の行ロックとバージョン検査で、確認画面を開いている間の変更を検出します。新APIが未適用の間、既存候補の閲覧はできますが追加・判断確定は利用できません。一般公開、会員募集、口コミ受付、本人用10店舗・期限は変更しません。

## 調査バッチの受け入れ

`src/domain/researchBatch.ts` がJSONの受け入れ形式です。`scripts/prepare-research-import.mjs` は検査済みJSONと既存店舗の対応表からSQLファイルだけを作り、DBには接続しません。実際の未承認100件バッチはフロントエンドに同梱しません。

対応表は researchId・既存UUID・既存名・既存住所が必須です。UUIDは一対一で、適用時のDBの店名と住所が完全一致しなければ中止します。既存の公式記録は上書きせず、確認済みの公式事実だけを未確認候補へ補います。矛盾した住所や外部資料は調査メモに残し、公開可能な事実にはしません。

同一バッチの再実行は厳密な変更なしです。削除した事実を復活させません。訂正・追加確認には新しいバッチIDと再確認が必要です。新しい調査記録と事実追加は同一トランザクションで店舗バージョンを更新します。公開・口コミが停止していること、全体200件以内を確認し、失敗時に部分取り込みを残しません。

Googleの評価・件数は取り込んでいません。管理画面にはキー不要のGoogleマップ検索リンクがあります。Google API導入は依頼者の指示で停止しています。キー設定・課金・API取得は行いません。

## 実利用パイロットへ残ること

この変更だけで一般公開・実口コミ受付・参加者拡張は始まりません。次の限定パイロットには、参加者3〜5名、開始・終了日、本人情報と表示内容への同意、独立した投稿審査担当、必要なAPIだけの許可が必要です。既存の固定ダミー投稿テストを、実際の口コミ受付と同じものとして扱いません。

店舗の承認後、参加者向けカタログ・本人プロフィール登録・実投稿・修正・通報・退会を既存のprivate review v2契約に接続し、期限・失敗時・未承認・別アカウント・削除を実HTTPとブラウザで確認する必要があります。一般公開と有料機能は、この限定パイロットとは別の判断です。
