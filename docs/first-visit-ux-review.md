# 初めて使う人のUI・UX点検

2026-10-11の保護Previewとソースを確認し、ホームから検索・詳細・比較・ログインへ進む流れを点検しました。ブランドの色、書体、ヒーロー写真は維持しています。一般公開やDBのアクセス権限を変更する点検ではありません。

| 不便さと根拠 | 利用者への影響 | 修正 | 検証方法 |
| --- | --- | --- | --- |
| 実Previewでホームの「個室」から0件画面へ進むと、ログインは「画面上部から」という文章だけ | スマホではメニューを探す必要があり、続け方が分からない | 空の一覧とホームに、その場で既存ログイン画面を開く操作を追加 | 320/390/430px・デスクトップで検索→ログイン→閉じる・Escape。検索語の保持 |
| ログインの戻り先は `?` より後を捨てていた | メールから戻ると検索をやり直す | 店舗検索に使う既知の条件だけ、長さ・値を制限して30分の戻り先に保持。メール・認証情報・外部URLは除外 | 許可する条件／不正URL／期限切れの単体試験、模擬メール認証から検索へ復帰 |
| アプリ内の移動で常に画面先頭にスクロールしていた | 下の店を見て戻るたび、元の場所を探し直す | 一覧の位置と選んだ店舗をメモリ内で保持し、戻ったときに位置とフォーカスを復元 | 詳細→一覧、ブラウザ戻るで位置とフォーカスを比較 |
| 本人用の比較が0〜1店のときは説明文のみ | 次のお店を選びに行きにくい | 選択数に合わせた見出しと「店舗一覧から選ぶ」を追加 | 0店→一覧→1店→比較→2店→比較 |
| 本人用の詳細に比較追加がない | 詳細を読んでから候補にするために一覧へ戻る必要がある | 詳細で追加・解除。比較から開いた詳細には「比較に戻る」 | 比較選択・詳細・戻り先と選択数の維持 |
| 本人用の検索0件が文章だけ | 条件解除の場所を探す必要がある | 「すべての実店舗を見る」を空結果のそばへ追加。店舗自体が0件の場合は再読込へ | 存在しない語→空結果→解除で10店へ復帰 |
| ホームが「個室・予算・アクセスから」と案内していたが、実装は確認記録の検索 | 個室の有無や予算額を厳密に絞れると誤解する | 「情報を確かめる」「キーワード」と表現。検索の意味は一覧の説明に集約 | 語の一致検索と実際の個室条件の区別、料金の種類・条件が失われないこと |
| 一般公開前の0件画面に空の料理選択などを表示していた。読込失敗でも0件と表示 | 未提供と通信障害が分かりにくい | データがないときは無効な絞込を省き、失敗は件数ではなく取得できない状態を表示 | 0件・読込中・503・再読込成功を区別 |

利用者向けの通常の店舗一覧・詳細には、架空プロフィールや投稿テストを出しません。運営管理と投稿テストはサーバーで確認した利用権限と専用画面で分離しています。本人用の10店舗という閲覧範囲は拡大しません。

検証用の認証・店舗応答はCI内の固定データです。実際のログインメール送信、プロフィール登録、口コミ投稿、DB書き込みは行いません。公開カタログ0件という現在の状態を、データが公開されたように見せる修正は含めません。
