# Executive Dining

React 19 / TypeScript / Vite 7 / Tailwind CSS 4 による会食店検索のプレビュー版です。

## 開発・検証

Node.js 22.18+（テストで TypeScript の型除去を利用）を使用します。

```sh
npm ci
npm run test
npm run lint
npm run build
npm run dev
```

## 現在利用できる機能

- 名古屋の公開許可済み情報を対象に、複数語・料理・確認できる情報で検索
- 公式の価格条件・休業情報・項目ごとの出典と確認日を一覧/詳細に表示
- 検索条件・店舗詳細・地図モードをハッシュURLに保持。戻る/進む/再読み込みに対応
- 実店舗の候補保存と最大3店の比較。比較リンクは店舗UUIDだけを含み、会社名・相手名・会食日時は含めない
- 権限を持つ編集者用の審査画面。メール/Googleログインは設定確認後の明示的な有効化が必要

公開gateがOFFなら実データ画面は0件です。旧6件サンプルとローカル口コミ下書きは明示したデモ画面に残しています。デモの情報・写真・評価・口コミは、実在店舗の公式掲載や実際の来店記録ではありません。実画面で公開口コミの受付は準備中です。

## 本番データ接続の前に必要な確認

1. 店舗情報の取得・掲載権限・正確性と写真の利用条件を確認し、モックとの区別を設計する。
2. 実際のSupabaseスキーマを確認する。既存 `supabase_setup.sql` にはフロントエンドの `reservation_status`、`reservation_url`、`smoking_policy` がないため、そのまま掲載登録できない。
3. 口コミの作者IDの検証、承認・編集・削除フロー、店舗掲載の権限を設計し、RLSを確認する。既存SQLのプロフィール公開範囲・ランク変更権限も見直す必要がある。この変更ではSQL／RLSを実行・変更していない。
4. 公開前に実際の利用規約・プライバシーポリシーと運営主体を用意する。存在しない規約への同意リンクは表示しない。
5. AIは現在準備中。プロバイダーキーを `VITE_*` 環境変数に入れるとブラウザに公開されるため、旧クライアント直接呼び出しは無効化した。再公開にはサーバー側の認証・レート制限・データ検証と費用管理が必要。既に公開済みのキーがある場合は管理者が利用状況を確認しローテーションする。

任意の接続設定：`VITE_SUPABASE_URL`、`VITE_SUPABASE_PUBLISHABLE_KEY`（旧`VITE_SUPABASE_ANON_KEY`も互換対応）。Googleログインは`VITE_SUPABASE_GOOGLE_LOGIN_ENABLED=true`、メールリンクは`VITE_SUPABASE_EMAIL_LOGIN_ENABLED=true`の別設定が必要です。いずれも設定確認まで初期OFFです。秘密鍵・service-roleキーはフロントエンドへ渡さないでください。

## 保存について

候補・比較選択・下書きはlocalStorageを利用し、このブラウザの同じオリジン内だけに保存されます。端末間・アカウント間の同期はありません。保存領域が使えないときはエラーを表示し、成功したと誤表示しません。共有端末では個人情報を入力しないでください。

GitHubのmain更新後に接続済みVercelが自動デプロイする想定です。設定や環境変数はこの更新では変更していません。

## 名古屋・実データ基盤（公開前の準備ブランチ）

通常のホームと主検索は名古屋の実データ用画面です。複数語・料理・確認できる情報・保存した候補から絞り込み、条件付きURLと店舗詳細へ移動できます。`#/curation` はDB権限で保護する審査画面。公開gateがOFFなら実画面は0件で、サンプルを補充しません。旧サンプルは`#/demo`と`#/search`に明示的なデモとして残しています。

- [設計・導入前の確認・未完了事項](docs/nagoya-launch.md)
- [10店舗の公式情報確認・候補データ・ライセンス資料](data/research/nagoya-2026-10-05/README.md)
- 基盤migrationと10件の候補は新しい専用DBへ承認のうえ適用済みです。公開・口コミ受付はOFF。source-eligibility追加SQLも承認のうえ適用済みです。過去SQLファイルの内容は保持しています。旧SQLの危険なpolicyは新DBへ持ち込んでいません。
- `npm run check`：単体/DB権限テスト、lint、build。`npm run test:e2e`：デスクトップ/モバイルUI。
- MapLibre/OpenFreeMapは地図を開いたときだけ接続し、利用者の現在地を取得しません。サンプルの座標や未確認の店舗位置はピンにしません。

実データの保存はUUID専用のブラウザ内保存で、旧サンプルの保存と混同しません。料金は公式コースの条件を保持し、平均予算への変換や価格ランキングは行いません。休業noticeは一覧/詳細の両方で表示します。地図は確認済みの位置だけを表示し、絞り込みでは背景styleを再作成しません。公開情報のcacheは短時間・メモリ内のみで、自動pollingはありません。

比較リンクは現在公開されている情報だけを再取得します。選択から掲載が取り下げられた店舗は表示せず、過去の保存内容から復元しません。クリップボードが使えない場合は手動コピー用リンクを表示します。リンクの送信は利用者が行います。

## 口コミ・訂正・通報の準備

実店舗詳細で、本人の訪問月・店舗との関係を含む体験下書き、公式情報の訂正メモ、口コミの通報メモをこのブラウザに保存できます。現在は送信・受付・公開しません。画面内移動での入力復元、明示的な削除、保存失敗/別タブ競合の表示に対応しています。下書きはログアウト後も同じブラウザに残るため、共有端末では保存しないでください。

将来用のreview adapterは未接続のv2契約案で、既存の未許可RPCへfallbackしません。[受付開始に必要な実装・運営判断・検証](docs/reviews-rollout.md)を確認してください。公開口コミの受付を環境変数だけで有効化する仕組みは追加していません。
